In development mode, when the application restarts after a change, the Pub/Sub module keeps what is expensive to create for the next generation:

* The `TransportChannelProvider` named `pubsub`, and with the emulator (`pubsub.emulator.host`) the gRPC channel to it, which the publishers and subscribers share.
* The `CredentialsProvider` named `pubsub` and the `GoogleCredentials` it holds, with the access token they cached.
* The publishers of the `@PubSubClient` methods, each with its gRPC channel, and the executor services they run on (`gcp.pubsub.publishing-executor` and each `gcp.pubsub.publisher.*.executor`). A message is serialized by each generation before it reaches the publisher, so a publisher holds nothing of the application. A publisher no client method of a generation used is shut down as that generation stops.

A change under `gcp`, of `pubsub.emulator` or of the executors (`micronaut.executors`) releases them: the next generation creates them again from the new configuration, and the released publishers and channel of the emulator are shut down. The credentials alone are released by a change under `gcp.credentials`. Nothing is kept when it was built from a bean of the application, such as a `TransportChannelProvider`, a `CredentialsProvider` or a `PublisherFactory` the application defines, nor are the credentials kept when they request their tokens through the Micronaut HTTP client (`gcp.credentials.use-http-client`).

The subscribers of the `@PubSubListener` methods run the application's code, so they are not kept. As a generation stops, its subscribers stop, and the next generation subscribes again on the kept channel and executors. A subscriber that stops processes the messages it has already received, and acknowledges them, before it terminates, so that the next generation receives only the messages that follow; with `gcp.pubsub.nack-on-shutdown` set, it nacks those it has not started to process instead, and Pub/Sub redelivers them to the next generation. A message that was received but neither acknowledged nor nacked when the subscriber terminated is redelivered once its acknowledgement deadline expires. Push subscriptions are removed from the push handler in the same way.

In place of a restart, a change of a `@PubSubListener` class stops its subscribers and subscribes again on the same channel, and a change of a serializer, an argument binder or a `@PubSubClient` recreates the registries and the client advice, which keep the publishers.
